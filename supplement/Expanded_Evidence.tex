\sect{1. What is being compared}
The main paper reports the selected progression from pre-optimized feasible designs, not only the later global-search extension. The 64-bit start is an RTL-search result after timing repair and power recovery; the 32-bit start is a fixed projection of previously searched RTL. Both already contain work from this project. They are not external industrial baselines, untouched upstream RTL, or solutions produced by independent competitors.

The fixed normalization references are different again. The 64-bit reference is a searched RTL realization whose 2.526346\,ns delay is infeasible under the final 2.40\,ns ceiling. The 32-bit reference uses the project's mask-based parity RTL. A reference supplies the energy denominator; it does not automatically supply a fair feasible starting point for every comparison.

\textbf{Why the early starting point is already optimized.} In the initial three-route episode, a model plan evaluates the searched reference, then a second RTL after a timing failure. Replanning with the two measured outcomes selects the third RTL, which first satisfies both the delay limit and score below one. Power recovery subsequently accepts two inverter downsizes. A matched control removes recovery while retaining the associated placement/routing steps and reproduces the earlier result; this is evidence for the specific recovery gain, not saturation of all physical optimization.

\textbf{Composition and rejection.} The pin/downsize/rotation milestone is the composition of two pin edits, selective downsizing, and a tree reassociation. The first pin edit was a direct-EDA prototype; the next pin edit and later reported operations used CHIA/Ray. A lower-area or faster intermediate is retained even when its energy score is worse. An inverter-absorption step, for example, improves the old path by 102.918\,ps but improves the whole design by only 35.009\,ps because a different path becomes critical.

\textbf{The later recovered local design.} A four-star trial on the earlier local circuit fails by 5.758\,ps. A single-star sibling produces a feasible intermediate. The following runtime call receives the earlier failure's path diagnosis and selects a two-star edit on that intermediate. The result has 37.465\,ps margin. Lower-energy local alternatives exist with 10.596 or 0.339\,ps margin, so this checkpoint is a headroom choice, not the globally lowest local score.

Full source paths and exact internal keys for these rows are in \path{evidence/expanded_results.csv} and \path{evidence/experiment_name_map.csv}. The immediate parent of the local shared-consumer branch is an unlisted \texttt{9eb} checkpoint; it is not silently connected to the preceding table row.

\textbf{How the projected RTL was generated.} The frozen candidate manifest specifies radix-2 parity trees, input-bit order $(1,4,2,3,0,5)$, a tree decoder with grouping $(a,b)=(1,2)$ and cross-grouping AB, and a self-inverse syndrome-basis shear $t_0=s_0\oplus s_1$. These are construction settings, not publication method names. The original corrected-data, syndrome, and error-status outputs are retained. The generator records 69 XOR2 operations in the linear stage plus one extra ideal XOR; these abstract counts are not mapped area. Functional and routed evaluation, rather than these counts, support the reported gain.

The original selector-based child had a generation failure; its corrected version later passed functional checks but reached 2.435600\,ns and failed the timing limit. That child is not part of the successful projected-start result. The originally logged mapped energy ratio mixed fidelities and was marked invalid; the routed score in this supplement uses only matching routed references.

\textbf{Conventional recovery versus new operations.} A fixed transfer of the 64-bit power-recovery recipe to the projected circuit makes zero resize moves. Netlist bytes and all reported metrics equal its own earlier flow. This supports a no-op conclusion for this specific circuit and recipe, not a claim that all physical methods are exhausted. Transferred phase pairs and subsequent runtime-selected star batches still improve the score.

\textbf{Feedback is not ancestry.} The three-star and four-star trials share the transferred-pair circuit as parent. The runtime reads the first trial's real measurements before selecting the four-star batch. Minimum-count and power-weighted binary plans likewise share the four-star parent. The mixed-arity single-group and final global plans share the power-weighted binary parent.

\textbf{What the certificate proves.} A count-11 witness plus a Boolean satisfiability (SAT) query reporting unsatisfiable for count $\leq10$ establishes the minimum XNOR2 count in the exact 41-variable, fixed-boundary XOR2/XNOR2 representation. It proves neither minimum energy nor globally minimum gate count. The power-weighted alternative ranks the prespecified first sixteen of seventeen count-11 candidates and selects the ninth.

Outer development then permits three-input parity consumers, increasing the phase variables to 56. The single-group trial improves delay and area while worsening the aggregate energy score. After seeing this, the runtime decides to evaluate the supplied global plan. Its nine changes comprise four XNOR2-to-XOR2, three XOR2-to-XNOR2, and two XOR3-to-XNOR3 replacements, leaving 10 XNOR2 and seven XNOR3 cells. Two bounded 22-second annealing workers used an area-first proxy and an XNOR2-count tie-break; no optimum certificate exists for this larger space.

\sect{5. Measurement contract, source levels, and effort}
\textbf{Electrical context.} SkyWater 130-nm high-density standard cells; typical corner, 1.8\,V, 25\,$^\circ$C; input slew 0.05\,ns; output load 0.005\,pF. The maximum external-output delay ceiling is 2.40\,ns. Rerouting uses a 2.575\,ns target and seed 20260921; the reported setup-repair recipe uses 2.35\,ns. The evaluator's virtual clock is 10\,ns. Clock slack is not the same quantity as $2.40-\mathrm{delay}$.

\textbf{Activity and energy.} Each workload supplies 1,024 vectors spaced 10\,ns apart, seed 2026092101. Stress uses unrestricted encoded-width input bits, including invalid codewords; uniform and low-toggle encode valid payloads. The latter changes one payload bit per vector. Over $10.24\,\mu$s, $E_w=P_wT/1024$ includes internal, switching, and leakage power. The normalized score is the geometric mean of the three ratios to a fixed reference of the same width. Raw workload energies are never averaged across widths or combined with a mapped-only ratio.

\textbf{Scope.} Functional gate waveforms have no delay back-annotation. These are activity-based estimates using routed parasitics, not silicon measurements or glitch-accurate power. The workloads were used during search. One nominal corner and no repeated-route confidence intervals bound the conclusions. Extra decimal places identify tool outputs; they do not express statistical uncertainty. Two-state equivalence and routed timing are not design-rule or layout-versus-schematic signoff.

\textbf{Source levels.} The data file contains 44 rows: 21 from the previously supplied receipt views, 20 earlier/reference milestones newly checked against the pinned Git summaries and command history, and three initial-selection rows read from the original Git receipt. New transcription does not create missing raw artifacts or constitute an independent EDA replay. The original 21 receipt files remain unchanged. Every row records its source path, label, and scope. A blank J\_reported field means no independent reported score was transcribed; its score is recomputed from the three energies, not counted as a second validation source.

\sect{6. Replay artifact and audit map}
\textbf{Historical versus portable execution.} The repository supplies saved-decision CHIA replay for the final 64-bit and 32-bit operations and an opt-in fixed-plan model gate. The 21-row replay subset and the 44-row selected evidence table serve different purposes. The CLI does not reproduce every historical catalog choice, coordinator query, or operator-development episode; the saved replay-data archive retains the original input bytes.

A saved 32-bit plan was executed from a clean exported checkout, and the 64-bit plan was executed from a source checkout; both returned valid proof, route, and measurement. The assembled code passes offline checking, both saved-plan preflights, and a mock STOP gate with zero routes. This packaging revision did not rerun EDA; live model endpoint use and installation on a second clean host remain unverified.
